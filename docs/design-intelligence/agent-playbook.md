# Agent Playbook — OT Design Intelligence

Use this playbook when asked to create or redesign a site, page or substantial section.

## Input

Capture before designing:

- business type;
- main visitor;
- primary commercial action;
- available proof;
- content quality;
- visual assets quality;
- constraints;
- current brand;
- mobile priority;
- performance constraints.

Unknown information stays unknown.

## Decision output

Before implementation, state:

1. **Design job** — what the interface must accomplish.
2. **Selected patterns** — IDs from `pattern-library.md`.
3. **Reference lenses** — only the systems that teach a useful principle.
4. **Client adaptation** — what changes to preserve client identity.
5. **Rejected patterns** — anything attractive but wrong for the task.
6. **Mobile plan**.
7. **Accessibility/performance risks**.
8. **Validation plan**.

## Example

Business:
local floriculture + baskets.

Design job:
help visitors understand occasions/products quickly and start an order.

Selection:
- P01 Commercial Hero;
- P06 Photo-First Catalog;
- P07 WhatsApp Conversion;
- P11 Local Discovery.

Reference lenses:
- Shopify for product/category hierarchy;
- Airbnb for photo-led discovery;
- Stripe for action clarity.

Rejected:
- P14 Atmospheric Background as dominant treatment, because it adds little to product choice.

## Implementation rule

Patterns define structure and behavior, not a fixed visual skin.

Never copy:

- source-brand color;
- proprietary type;
- logos/assets;
- distinctive branded layout;
- brand-specific copy.

Use the project's real identity.

## Review checklist

Before approval:

- can the visitor understand the offer in the first meaningful viewport?
- is proof visible before large promises?
- is one primary action obvious?
- does mobile preserve the same decision hierarchy?
- do interactive states work by keyboard/touch?
- is any animation decorative noise?
- are client names/images uncropped?
- are references still invisible in the final brand identity?
