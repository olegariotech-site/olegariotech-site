# Pattern Library

Patterns are selected by **job**, not by brand reference.

## P01 — Commercial Hero

Use when:
- visitor must understand the business in the first viewport.

Required:
- clear offer/category;
- supporting value;
- primary CTA;
- optional secondary CTA;
- proof cue when available.

Useful reference principles:
- Stripe: clarity and CTA hierarchy.
- Framer: confident composition.
- Apple: one dominant subject.

Avoid:
- atmospheric hero with unclear service;
- multiple equal CTAs;
- visual effect covering the offer.

---

## P02 — Cinematic Showcase

Use when:
- visual quality is itself proof;
- portfolio/project imagery deserves protagonism.

Useful reference principles:
- Framer: dark artboard + spotlight moments.
- Webflow: show work while explaining it.
- Apple: media as protagonist.

Structure:
1. project/client;
2. visual;
3. short commercial context;
4. real/concept status;
5. action to inspect.

Avoid:
- auto-heavy carousels;
- hidden client names;
- motion that competes with reading.

---

## P03 — Proof Before Promise

Use when:
- trust matters more than feature volume.

Structure:
1. claim/problem;
2. evidence;
3. interpretation;
4. CTA.

Proof can be:
- real project;
- verified review;
- screenshot;
- measured before/after;
- location/reputation fact.

Useful reference principles:
- Stripe: proof near claims.
- Linear: quiet credibility.
- Webflow: visual demonstration.

Avoid:
- invented metrics;
- anonymous testimonials without context;
- badges that imply certification when none exists.

---

## P04 — Service Family Grid

Use when:
- business has several service categories.

Useful reference principles:
- Linear: disciplined cards.
- Stripe: benefit-first explanation.
- Spectrum: consistent component states.

Card anatomy:
- service name;
- short benefit;
- optional evidence/qualifier;
- action/details.

On mobile:
- stack or 1-column;
- no tiny 3-column squeeze.

---

## P05 — Progressive Disclosure / Accordion

Use when:
- secondary detail would otherwise overload the page.

Good:
- FAQ;
- process detail;
- technical explanation;
- policies;
- service sub-details.

Useful reference principles:
- Spectrum: accessible states.
- Linear: low-noise disclosure.

Never hide:
- main offer;
- core proof;
- primary CTA;
- essential price;
- information required to choose.

Prefer native `details/summary` when adequate.

---

## P06 — Photo-First Catalog

Use when:
- visual product choice drives action.

Useful reference principles:
- Airbnb: image-led discovery.
- Shopify: category/product hierarchy.
- Apple: subject spacing.

Card anatomy:
- real photo;
- product/category name;
- useful metadata;
- price when approved;
- clear order/consult action.

Avoid:
- decorative overlays obscuring products;
- inconsistent crops;
- fake lifestyle imagery presented as real inventory.

---

## P07 — WhatsApp Conversion Path

Use when:
- sale closes conversationally.

Structure:
1. context/offer;
2. enough information to reduce basic questions;
3. CTA with prefilled intent;
4. optional secondary Maps/call action.

Rules:
- do not make WhatsApp the only explanation;
- preserve source/context in message where possible;
- mobile target must remain reachable;
- do not cover content.

---

## P08 — Process / Method Timeline

Use when:
- client anxiety comes from not knowing what happens next.

Useful reference principles:
- Stripe: explain complexity in layers.
- Linear: restrained structure.
- Apple: sequential storytelling.

Structure:
- 3–5 meaningful stages;
- each stage = action + client consequence.

Avoid:
- decorative 8-step process;
- invented certainty;
- technical jargon without consequence.

---

## P09 — Feature / Benefit Split

Use when:
- service has technical features that need commercial translation.

Format:
- capability;
- what it changes for the customer;
- proof/condition where available.

Useful reference:
- Stripe.

Avoid:
- feature dumps;
- claiming outcome as guaranteed.

---

## P10 — Editorial Trust Page

Use when:
- expertise, authority and reading comfort matter.

Useful reference principles:
- Resend: editorial hierarchy on dark.
- Apple: whitespace.
- Linear: quiet surfaces.

Good for:
- law;
- consulting;
- institutional pages;
- founder story;
- detailed service explanation.

Avoid:
- over-animation;
- dense decorative cards around every paragraph.

---

## P11 — Local Discovery Strip

Use when:
- proximity/location affects choice.

Structure:
- area served;
- map/directions CTA;
- real local proof;
- contact route;
- optionally neighborhood/service-area context.

Useful reference principles:
- Airbnb: location/discovery.
- Shopify: action clarity.

Avoid:
- fake address;
- doorway-page copy;
- city-name stuffing.

---

## P12 — Comparison / Pricing Choice

Use when:
- visitor genuinely needs to compare options.

Useful reference principles:
- Stripe/Linear/Framer pricing systems.

Rules:
- compare meaningful differences;
- highlight one option only if justified;
- disclose exclusions/conditions;
- do not use fake anchoring.

Avoid:
- three packages created only to push the middle one;
- unclear media/software/third-party fees.

---

## P13 — Sticky Contextual CTA

Use when:
- long page benefits from persistent next action.

Useful reference principles:
- Apple sticky purchase bars;
- local WhatsApp utility.

Rules:
- small;
- unobtrusive;
- disappears/reduces when overlapping primary content;
- accessible label;
- respects safe areas on mobile.

---

## P14 — Atmospheric Background

Use when:
- atmosphere strengthens identity without carrying essential information.

Examples:
- OT Earth/particles;
- subtle glow;
- slow ambient movement.

Useful reference principles:
- Framer/Resend.

Rules:
- background only;
- no essential message encoded in motion;
- reduce/disable on low-power/mobile/reduced-motion;
- never compete with text.

---

## P15 — Browser / Device Proof Frame

Use when:
- showing the actual digital product is persuasive.

Useful reference:
- Webflow.

Rules:
- frame is secondary;
- screenshot remains readable;
- use real project media;
- mobile frame only when it adds context.

Avoid:
- fake dashboards;
- decorative browser chrome repeated everywhere.

---

## Pattern composition rule

Default maximum for one section:

- 1 primary pattern;
- 1 supporting interaction pattern;
- 1 atmospheric treatment.

Do not stack three visual metaphors in one section.
